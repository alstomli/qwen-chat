# Request diagnostics

Set the server-side environment variable `CHAT_DIAGNOSTICS_ENABLED=true` on both the updated gateway and the frontend. This opt-in works in development, Vercel Preview, and production; it defaults off everywhere. On Vercel, set the variable for the intended environment and redeploy to apply it. The existing session authentication and same-origin checks remain required. The authenticated gateway `/health` advertises `diagnosticsVersion: 1` only when enabled. The frontend's authenticated `/api/status` reports `diagnosticsAvailable: true` and `diagnosticsVersion: 1` only when both services are enabled; older/disabled gateways keep the toggle hidden. Sample-reply preview mode cannot provide tokenizer diagnostics.

Open **Your workspace → Advanced settings → Request diagnostics**. The toggle starts off and affects new requests only; it does not alter message selection, token limits, sampling, or prefix-reuse policy. Each captured reply has an expandable panel showing exact input token counts before/after gateway trimming, removed tokens, output/context budgets, safety reserve, unreserved space, browser/gateway trimming separately, finish reason and vLLM-reported usage when available. The first count already includes system instructions, the served chat template and generation marker, and starts after browser message/byte trimming. Browser byte counts describe the message array serialized as UTF-8 JSON, not tokens or the full request. The gateway reuses its existing tokenizer calls, without extra tokenization requests. A rejected request may have a last tokenizer count but no final input confirmed for generation.

Diagnostic metadata travels in `X-Chat-Diagnostics`; the proxy forwards only a validated versioned summary. Actual usage is requested with `stream_options.include_usage` and read from the final usage-only SSE event. Missing usage/finish reason stays **Unavailable**; stop, error and interrupted states preserve partial records. The parser never counts network chunks as tokens. Prefix reuse is shown as **allowed/bypassed**, not a measured hit. A disagreement between the final tokenizer count and vLLM prompt usage is flagged for investigation.

**Copy record** exports one allowlisted JSON summary. **Export CSV** exports that request; **Export session CSV** in workspace settings exports the latest 100 captured requests across chats, including their status. CSV cells escape quotes/newlines and guard spreadsheet formulas. Summary copy and CSV exports exclude prompts and answers. The separate **Export trace JSON** action includes the full captured text described below. Credentials, cache salts, binary images, and hidden reasoning fields are excluded from all exports. Records and the toggle live only in React memory: reloading or signing out clears them, and nothing is automatically saved to local storage, logs, or disk. Capturing a diagnostic does not change ordinary conversation saving. Files are created only on explicit export. Existing records remain available when the toggle is switched off.

The diagnostics integration test uses a fake model; its tokenizer/usage counts validate transport and UI plumbing, not the real model's tokenization. When Docker is unavailable, use an isolated Python environment containing `httpx`, `fastapi`, and `uvicorn`, set `CHAT_TEST_FIXTURE_PYTHON` to its executable (and `PYTHONPATH` if using a target directory), then run `node scripts/integration.mjs`. Without that variable the test uses the existing Docker fixture. Both paths are localhost-only from the host, opt in to diagnostics explicitly, and clean up their processes after testing.

### Measure responsiveness (learning stage 2)

Request diagnostics now includes browser and gateway durations, and Copy record / CSV exports include the same fields. Browser measurements use `performance.now()` from the accepted Send handler invocation, including local validation/history fitting and the Next.js proxy path:

- **First content received** ends at the first nonempty parsed assistant content, excluding empty/role-only/usage events.
- **First answer rendered (paint estimate)** is recorded separately after nonblank rendered answer text is committed to the DOM, intersects the viewport, and gets a double-animation-frame paint opportunity in a visible tab. It is an estimate, not an exact compositor/display timestamp. Hidden tabs, offscreen answers, navigation, and Markdown-only partial chunks can delay it or leave it unavailable. It can follow stream completion for very short replies.
- **Response completed** ends when the parser receives `[DONE]` successfully. **Request ended** also covers stop/error paths. Stop/error leaves completion unavailable while keeping first-content/render measurements already observed.

Gateway durations arrive in a named `chat-timing` SSE event at stream end, and are accepted only when its request ID matches the validated header. They cover context fitting (including tokenization and trimming), upstream POST to first content, gateway entry to first content, and gateway entry to stream end. Old gateways continue to work with unavailable gateway timings. Metadata uses an allowlist, is session-only, and contains no prompts, answers, secrets, or absolute cross-machine timing timestamps. Never compare wall-clock timestamps between machines or subtract browser/engine p95 values. Grafana remains the source for engine TTFT/ITL/queue metrics.

Start with the [manual pilot worksheet](responsiveness-pilot.md). Deploy the gateway change and frontend through their usual release processes to collect both layers against the live model; the local fixture only verifies instrumentation.

For optional real-browser assertions during `node scripts/integration.mjs`, set `CHAT_TEST_PLAYWRIGHT` to the absolute path of an installed Playwright `index.mjs`. Use its installed Chromium, or set `CHAT_TEST_BROWSER_CHANNEL=msedge` (or `chrome`) for an existing browser. The isolated headless browser signs in only to the local fake-model test app, verifies that two conversations stream together, Stop cancels only the selected reply, the other reply completes, and timing records stay with their replies. No browser package is needed for the default HTTP integration test.


## Hosted request budget

On Vercel the application deadline is 240 seconds from chat-route entry, including authentication, body validation, gateway readiness, queueing and generation. The gateway receives the remaining budget; diagnostics describe that effective budget rather than the original longer browser preference. A shorter requested timeout or web-search cap takes precedence. Local custom timeouts remain available. The platform route limit remains 300 seconds to leave cancellation/response headroom.

### Exact model requests and responses

When diagnostics is enabled, **Model request trace** groups exact requests by Chat, Planning 1–4, and Final answer. Expand each message to inspect its system/user/assistant/tool role and exact associated text, including tool schemas/choice, arguments and results. Snapshots are immutable and captured after fitting at the actual model send boundary. Model/adapter, max tokens, temperature, effective settings, available response text/tool calls, usage, finish reasons and bounded failures are included. Image parts retain associated text and show a binary placeholder. Hidden reasoning fields are excluded; visible model response text is preserved, including failed or length-limited planning responses.

Trace JSON is an explicit download only. It can contain private conversation text and tool evidence. Traces stay separate from conversation/cloud history, browser storage, ordinary chat exports and CSV summaries. Reload or sign-out clears them. Turning diagnostics off captures/transmits no prompt traces for new requests and unsolicited trace events are rejected.

Version 1 `chat-trace` SSE events use ordered request-bound chunks (4 KiB decoded UTF-8 maximum), followed by `chat-trace-end`. The authenticated route validates complete records before forwarding their chunks; malformed or unvalidated partial gateway records never reach the browser. The browser preserves already received partial records or unfinished frames explicitly as incomplete. HTTP model failures keep their failure status and use a bounded validated JSON trace carrier. Older gateways may provide summary measurements without a full trace.

Each request permits 32 MiB of decoded JSON records. The conservative budget allows five requests of up to 640,000 bytes, up to sixfold JSON escaping, and response/tool evidence overhead. Individual framed chunks are limited to 32 KiB; buffered framed record transport is bounded to 96 MiB. Limits never silently truncate records: exceeding the gateway budget marks the trace incomplete; invalid transport fails closed. A stopped/disconnected request can lack final usage or terminal trace metadata. The inspector labels these traces incomplete. This is a finite diagnostic budget, not an unlimited transcript service.

The tab retains up to eight full traces and 96 MiB using conservative UTF-8 plus UTF-16 accounting. Older full traces and partial buffers are visibly evicted; up to 100 measurement summaries remain. Plain text rendering prevents tool excerpts from becoming executable markup. Full JSON export preserves the exact captured records, completion status and received partial text.

Validation: synthetic tests cover fitted ordinary requests, native tool/final-system rewrites, Unicode/coalesced chunks, malformed/cross-request/unsolicited events, failure status, partial receipt and eviction. A single focused private real-model sample completed both the original price question and its contextual follow-up with complete traces matching every actual model request; final answers and usage were received. The follow-up used 335 planner tokens in that sample, so this does not establish deterministic reproduction of the earlier 512-token failure. The 2048 cap and aggregate reserve are verified independently by synthetic tests. Browser acceptance remains incomplete: local fixture connections timed out despite the dev server becoming ready. No production deployment was performed.
